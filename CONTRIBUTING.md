# Contributing

Issues and pull requests are welcome.

This repository is synced from the DesktopEngine app's repository: the SDK evolves together with the app's runtime (a new API changes the type declarations and the implementation at once), so changes land in the app's repository first and are synced here. Once your pull request is accepted, a maintainer applies it to the app's repository; the commit synced back keeps you as its author, and the pull request is closed.

## Development

The SDK is written in TypeScript: `src/` is the command line tool, `test/` the tests, and `npm run build` compiles them with `tsc` into `dist/` (what npm publishes, for Node.js 18+). Sources import each other with `.ts` extensions, rewritten to `.js` when compiled, and only use erasable syntax (no `enum`, no parameter properties), so Node.js 22.18 and later run the sources directly, with no build while developing:

```bash
npm install         # installs the dependencies and builds dist/ (prepare)
npm link            # optional: the desktopengine command runs this build
npm start -- dev ~/Projects/day-progress   # runs src/cli.ts directly
npm test            # unit tests: manifest rules, zip, templates, builds, the dev server, the command line
npm run typecheck   # checks the sources and tests, and every template against the type declarations
npm run build       # compiles into dist/
```

- `src/`: `cli.ts` is the entry; `manifest.ts` holds the manifest rules, the same as the app's; `build.ts` bundles a mini program's `src/` with esbuild; `dev.ts` and `websocket.ts` are `desktopengine dev`, see the [dev protocol](docs/reference/dev-protocol.md) for how it talks to the app.
- `templates/`: the project templates of `create`, kept small as a starting point. `<type>-<renderer>/` (e.g. `wallpaper-three`) are the versions of `create --renderer`, see `RENDERERS` in `src/project.ts`.
- `types/desktop-engine.d.ts`: the type declarations of the runtime API, kept to what the engine really provides.
- Code comments and command line output are in English.
- Commit subjects follow [Conventional Commits](https://www.conventionalcommits.org): `feat(cli): …`, `fix(types): …`, `docs: …`. `feat` and `fix` subjects become lines of `CHANGELOG.md`, so write them for the SDK's users; a breaking change has a `!` before the colon (`feat(cli)!: …`).

## Documentation

`docs/` is the documentation site (VitePress), in English with a Chinese translation under `docs/zh/`; update both when you change a page. The API reference is generated by TypeDoc from `types/desktop-engine.d.ts`:

```bash
cd docs
npm install
npm run dev         # preview locally
npm run build       # builds into docs/.vitepress/dist/
```

GitHub Actions publishes it to <https://desktopengine.github.io/desktopengine-sdk/> after a push to `main`.

## Releases

A release is made in the app's repository: the next version comes from the commits since the last one (a breaking change makes a major version, a feature a minor one, a fix a patch), their subjects become the version's section of [`CHANGELOG.md`](CHANGELOG.md), and `package.json` gets the new `version`.

When the `version` in `package.json` changes on `main`, GitHub Actions checks, tests and publishes it to npm (with provenance, through npm trusted publishing), then creates the `v<version>` tag and the GitHub release, with the version's section of `CHANGELOG.md`. Versions with a prerelease suffix (e.g. `0.2.0-beta.1`) go to the `next` tag.
