# 窗口

内容的画面画在 `new DesktopEngine.Window({ type })` 创建的原生窗口里。

| type | 用途 |
| --- | --- |
| `desktop` | 壁纸：桌面层，在桌面图标之下，所有空间可见，也能收到鼠标移动 |
| `widget` | 贴在桌面上的小组件：桌面图标之上，无边框、背景透明，可拖动 |
| `overlay` | 浮于所有窗口之上：无边框、背景透明，所有空间和全屏应用上都可见，用于浮动小组件和桌面伙伴 |

窗口显示时不会激活 DesktopEngine，不会抢走用户当前应用的焦点。用户不能调整窗口大小，但清单允许时可以调整小组件的窗口：见[小组件的大小](#小组件的大小)。

内容只能创建一种窗口，由它的类型和用户放的位置决定，运行时强制执行：壁纸用 `desktop`，桌面伙伴用 `overlay`，小组件贴在桌面上时用 `widget`、浮于所有窗口之上时用 `overlay`。传入 `launchOptions.windowType` 即可；其他类型或不写 `type`，`new DesktopEngine.Window()` 会抛出错误。`desktopengine dev` 和「开发」菜单载入的内容也一样，发布前就能发现；没有启动参数时（「开发」菜单）小组件用 `widget`，伙伴用 `overlay`。

窗口本身是透明的，样式不支持圆角：需要圆角时，在 Canvas 上画圆角矩形（见小组件模板）。窗口创建后会一直存在，直到调用 `destroy()`。

内容同时最多有 16 个窗口，再创建时 `new DesktopEngine.Window()` 会抛出错误，所以不用的窗口要 `destroy()`。`widget` 和 `overlay` 窗口不会盖住菜单栏，最多占一块显示器的一半：放得更高的会被移下来，更大的会被缩小（内容被裁掉）。小组件自己的窗口按[小组件的大小](#小组件的大小)里的规则来。要在整个屏幕上活动的桌面伙伴，用一个跟着它移动的小窗口。

## 小组件的大小

清单写了 `"apiVersion": 8` 或更高时，小组件的窗口是它显示的第一个没有父窗口的 `widget` 或 `overlay` 窗口，直到这个窗口关闭。它的大小是用户选的尺寸，即 `launchOptions.width` × `launchOptions.height`，按这个大小创建窗口：

- 除非 `widget.resize` 允许内容调整（见[小组件尺寸](/zh/reference/manifest#小组件尺寸)），不管样式怎么写，窗口都保持这个大小。
- 窗口留在所在显示器的可用区域内：菜单栏之下，不挡住程序坞。设了 `hitRegion` 时，左、右、下三边只要求接收鼠标的部分（各矩形的外框）留在可用区域内，小组件周围透明的边距（例如留给阴影的）可以在屏幕外或程序坞上，小组件可以紧贴屏幕边缘；窗口的上边仍然在菜单栏之下，所以画的内容上方少留空白。用户拖动小组件时它跟着指针走，哪里都能去（只有菜单栏挡住它）；松手后在四分之一秒内滑回可用区域，落在指针所在的显示器上，滑动途中会触发 `move`。比可用区域大时按原比例缩小；`widget.resize` 允许改变形状（没有 `"aspectRatio": "fixed"`）时，宽和高各自限制在可用区域内，再不小于它允许的最小尺寸。`launchOptions.width` 和 `height` 已经是调整后的。除此之外大小没有限制。
- 窗口得到的位置或大小和样式要求的不同时，样式会改成实际的值，并触发 `resize`（读窗口的 `width` 和 `height`）或 `move`。
- 为了留在屏幕上而被挪动只是暂时的：贴着屏幕边缘（或往上伸进菜单栏）变大的小组件会被推进来，变小到放得下时回到原来的位置，你固定的那个角也回到原处。只有用户拖动或内容自己移动（保持大小、设 `left` / `top`）才会换位置；从被推到的位置出发设新的大小（例如为了让某个角不动）不算移动。所在的显示器也一样：用户把它拖放到另一块显示器上，或者你的内容把它移过去（改不改大小都算）时才换。只改大小的小组件留在原来的显示器上，即使保持某个角不动会伸到旁边的显示器上也一样。它在哪块显示器上，看的是接收鼠标的部分（`hitRegion`），不是透明边距伸到了哪里。

`"by": ["user"]` 时，用户像调整普通窗口一样拖小组件的边和角来调整大小，指针在小组件上停一会儿后，右下角外面会出现一小段玻璃质感的弧线，顺着小组件画出来的圆角，提示它可以调整大小（指针在小组件上、在那个角上或在弧线上时一直显示）；按住其他地方仍然是拖动，单击仍然只是单击。拖动时窗口会触发 `resize`，每帧最多一次：按新的大小重新布局和绘制。`"by": ["content"]` 时，内容自己设置窗口的 `width` 和 `height`（移动时还有 `left` 和 `top`），例如一个越来越长的列表；窗口保持在范围内，只有得到的大小和要求的不同时才触发 `resize`。不管是谁调整的，应用都会记住小组件的大小和位置，下次在那里启动。应用详情栏里的预览按所选的尺寸运行。

为更早的 API 做的小组件保持原来的规则：它的窗口和上面所有 `widget`、`overlay` 窗口的规则一样。

## 鼠标

- `widget` 和 `overlay` 窗口按住任意位置就能拖动（系统原生拖动）：拖动时依次收到 `mousedown`、窗口的 `move` 和松手时的 `mouseup`，拖动过程中没有 `mousemove`；单击只收到 `click`，没有 `mousedown` / `mouseup`。
- 窗口的 `dragRegion` 限定按住哪些地方会拖动窗口，其余地方的按下和拖动交给组件（`mousedown`、按住时的 `mousemove`、`mouseup`），适合表盘、滑块这类控件；`null`（默认）是整个窗口，`[]` 是哪里都不拖动。
- 不拖动窗口的按下（`dragRegion` 以外，或在 `desktop` 窗口上）依次收到 `mousedown`、`mouseup`、`click`，和浏览器一样，让 DesktopEngine 来到前台的那一下也是；松手前移动超过 3 点的不算单击。双击的第二下在 `click` 之后还有 `dblclick`。每个事件先给指针下的组件，再依次给外面的组件，直到窗口。
- 窗口拖到屏幕边缘松手后，大小不变，停在松手的位置，不过 macOS 仍会显示平铺的预览。
- 窗口的 `hitRegion`（以窗口左上角为原点的矩形数组，单位点）限定只有这些地方响应鼠标，其余地方的点击、拖动和悬停都会穿透到下面的窗口；`null`（默认）是整个窗口。窗口透明的地方默认仍然会接住鼠标，不规则形状的桌面伙伴应随画面更新它（见 companion 模板）。
- `mouseenter`、`mousemove`、`mouseleave` 在窗口不是当前窗口时也会触发。
- 指针停在 `widget` 或 `overlay` 窗口响应鼠标的地方（它的 `hitRegion`，没有就是整个窗口）时，窗口会收到 `wheel`（API 8），不会抢走用户正在用的应用的焦点：从指针下的组件开始，经过外层的组件，一直到窗口。增量是系统给的，大约以行为单位：用户往顶部滚时 `deltaY` 为正（开着自然滚动时就是手指在触控板上往下移，所以跟着 `deltaY` 移动的内容和手指同向）；触控板会发很多小的增量，手指离开后还会继续发一会儿。API 8 之前滚轮只给当前的 key window，桌面上的窗口从来不是。
- 事件回调的参数是普通对象，`this` 是触发事件的对象。鼠标事件和 `click`、`dblclick` 的字段与 DOM 的 `MouseEvent` 同名字段一致：组件里的 `x`、`y`，修饰键，`button`（按下或松开的那个键）和 `buttons`（按住的键）。每个键都有 `mousedown` 和 `mouseup`；只有主键会触发单击、拖动窗口。

## 键盘

内容收不到键盘输入：打字总是交给用户正在用的应用。请按鼠标操作来设计；需要用户输入文字时，用[选项](/zh/reference/manifest#选项-parameters)。

## 显示器和缩放

- `launchOptions.display` 是内容所在的显示器，`frame` 是整块屏幕，`visibleFrame` 去掉了菜单栏和程序坞。它在启动后不会变：`DesktopEngine.ScreenManager.screens` 里是每块显示器当前的 `bounds` 和 `visibleFrame`，它们变了（比如用户调整程序坞的大小、位置或把它隐藏）`ScreenManager` 会触发 `change`。沿着底边走的桌面伙伴这时重新读一次所在显示器的 `visibleFrame`。
- 窗口的 `devicePixelRatio` 是所在显示器的缩放比例。小组件、桌面伙伴被拖到缩放比例不同的显示器上（例如从 Retina 屏拖到 1x 的外接显示器），或者用户改了显示器的分辨率，它会改变并触发窗口的 `devicepixelratiochange` 事件，这时按新的值重设画布的 `width` / `height`、重画。
- 注意这里改 `width` / `height` 不会重置 2D 上下文的状态（浏览器会），缩放用 `setTransform(ratio, 0, 0, ratio, 0, 0)` 重设，不要再叠加一次 `scale()`（见 widget、companion 模板）。

完整的属性和事件见 [`Window`](/api/interfaces/DesktopEngine.Window)。
